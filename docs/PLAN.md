## Этап 2 — задача, где языковой опыт может помочь
Без этого звено 2 непроверяемо. Исходное предложение — мерить скорость адаптации к новой версии среды — отложено: «поколение до уровня» при Adam растёт с числом параметров головы (выведено, не проверено), и без уравнивания параметризации выиграет просто модель покрупнее.

Новое предложение (2026-10-01): дать агенту своё время — окно из N последних кадров в контексте LM — и задачу, которая без памяти не решается. Набросок — `env_flip.py` («смена знака»: два вида предметов, какой из них пища, а какой яд — монетка эпизода, узнаётся только по последствиям съеденного). Предварительные проверки эвристиками, 200 эпизодов:

| политика | приспособленность |
| --- | --- |
| стоять / случайно | 0,490 / 0,512 |
| жадно к любому, без памяти | 0,495 ± 0,391 |
| с памятью, окно 1 / 2 / 4 / 8 / 16 / 32 | 0,518 / 0,609 / 0,692 / 0,903 / 1,074 / 1,122 |
| оракул (знает знак) | 1,373 ± 0,251 |

Барьер против политики без памяти есть (0,88, 2,2 ст. откл. на эпизод), выгода растёт с окном монотонно — зависимость от N сама по себе мера «времени у агента». Не проверено: может ли ES найти обход через тело (память в позиции/курсе) — это надо смотреть по обученным агентам.
- [x] Набросок среды и эвристические проверки (`python env_flip.py`)
- [ ] Окно истории в политике: LM с N·K псевдотокенами; контроли — линейная и муха на окне той же длины (память без LM), **рекуррентная муха** (память без окна и без LM), LM со случайными весами, предобученная, **LM с перемешанным порядком кадров в окне** (кадр = K векторов, переставляются кадры целиком); кривая по N
- Память в теле (позиция/курс как хранилище) — биологически законна, но здесь помеха: **измерять, а не запрещать** — по обученным агентам, напр. сбросом позиции/курса при сохранённом окне.

**Контроль с перемешанным порядком диагностичен не везде** (эвристики, 200 эпизодов, `python env_flip.py [--reversal]`). Политика «последнее событие в окне» против политики «мешок» (голосование всех событий окна, порядок не нужен):

| окно | знак постоянен: последнее / мешок | с разворотом: последнее / мешок |
| --- | --- | --- |
| 8 | 0,903 / 0,903 | 0,774 / 0,778 |
| 16 | 1,074 / 1,076 | 0,936 / 0,916 |
| 32 | 1,122 / 1,123 | 0,974 / 0,791 |
| всё (100) | 1,122 / 1,123 | 0,974 / 0,609 |

Без разворота порядок не нужен вовсе — перемешивание не уронит и честно читающую последовательность модель (установлено эвристиками). С разворотом порядок нужен только при окне длиннее ~16 кадров: короткое окно само забывает старое и заменяет порядок. Значит, серия этапа 2 — с разворотом (`reversal=True`) и окном ≥ 32 кадров, иначе контроль ничего не скажет. Цена разворота: потолок эвристики 0,97 против оракула 1,36.

**Стоимость окна (оценка, не замер).** Окно 32 кадра × 2 вектора = 64 позиции × 64 тела = 4096 позиций на проход. Qwen2.5-1.5B (~1,3 млрд без эмбеддингов) в fp32: ~1·10¹³ FLOP на такт; на RTX 5050 Laptop (~13 TFLOPS fp32 пик, реально половина) ~1,5 с на такт → ~2,5 мин на поколение → ~1,5–2 ч на прогон → 10 посевов × 2–3 LM-условия = 30–60 ч. Для ноутбука неприемлемо. Выход — **KV-кэш с контекстом во весь эпизод** (100 кадров = 200 позиций): на такт считаются только 2 новых вектора на тело (128 позиций — как сейчас), проход упирается в чтение 6 ГБ весов (~20–30 мс), ~3 с на поколение. Кэш: 28 слоёв × 2 × 256 × 200 × 64 × 4 байта ≈ 0,7 ГБ — вместе с весами впритык к 8 ГБ, мерить. Скользящее окно N < T с кэшем требует маски внимания — кривую по N снимать на малых моделях пересчётом, на 1,5B — только «окно = эпизод». Проектор фиксирован внутри эпизода, поэтому кэш точен; при пластичности при жизни (этап 3) это перестанет быть так.
