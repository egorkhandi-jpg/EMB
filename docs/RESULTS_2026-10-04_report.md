# Звено 4: отчёт и тело

## Пререгистрация (записано до расчёта)
Решение Егора 2026-10-04, вариант A. Без обучения LM, ноутбук. Изменение не среды — бюджет не расходуется. Код — `report_body.py`, метка `v4-report`. Результаты — `results_report/`.

**Вопрос.** Доступно ли состояние тела языковому каналу замороженной LM: предсказывают ли логиты ответных символов состояние тела выше копирования и выше случайной сети, на переменной, которой нет в окне буквально?

### Данные
- `flip-2` с разворотом, слепая политика (рефлекс к ближайшему предмету любого вида). 10 наборов × 100 эпизодов, посевы 800000 + 1000·i + e (новые).
- Интерфейс c + BOS, окно 32 такта. До начала эпизода окно дополнено кадрами ' none' ' same', чтобы длина была постоянной для пакета; у `LMWords` в начале эпизода окно просто короче.
- **Запросы** — информированные такты t ∈ {12, 16, …, 96}, где у тела есть метка на t − 8 (нужна для few-shot); ≈ 900 запросов на набор.
- **Модели:** Pythia-160M и Pythia-1B, fp32, предобученная и случайная (сеть от набора, эмбеддинги приведены к средней норме предобученной, как в стенде).

### Переменные тела (на информированных тактах)
- **знак эпизода** — основная: в окне его нет буквально, это связка вида и исхода;
- последний исход (пища / яд) — описательно: лежит в окне почти буквально.

### Режимы вопроса
К окну дописываются символы вопроса; читаются логиты ответных символов на следующей позиции. Мера — разность логитов (' A' − ' B').
- **zero-shot**: ' Food:', ' Safe to eat:', ' Good kind:' → ' A' против ' B'. Результат — среднее по трём шаблонам на набор, разброс — описательно.
- **few-shot**: перед вопросом 4 прошлые пары «' Food:' ответ» из того же эпизода. Ответ — метка тела на t − 8, t − 6, t − 4, t − 2 (' A', если «последний исход» говорит, что A — пища, иначе ' B'), оракула нет. Затем ' Food:'.
- **произвольные символы**, few-shot: вопрос ' chair', ответы ' door' (A) / ' stone' (B) — описательно.
- **перемешанный порядок кадров окна** (кадры целиком; вопрос и пары — на месте) для zero-shot ' Food:' и few-shot — описательно.
- последний исход: ' Energy:' → ' up' против ' down' — описательно.

### Контроли
- случайная LM с теми же символами;
- **копирование** — ответ = вид последнего съеденного, без учёта исхода (базовая линия);
- **«последний ответ примера»** (добавлено, описательно) — ответ = ответ последней few-shot пары, то есть метка тела на t − 2;
- линейный зонд по скрытому состоянию на позиции вопроса (zero-shot ' Food:' и few-shot) — верхняя граница. λ по CV с группами-эпизодами, решения на отложенных эпизодах (5 частей), AUC.

**Оговорка, записанная до расчёта.** В few-shot ответы прошлых пар — метка тела, а она почти всегда равна текущему знаку: между событиями метка держится. Few-shot можно пройти копированием последнего ответа примера, без доступа к окну. Поэтому положительный few-shot толкуется как «аппарат отвечает о теле по контексту», только если AUC выше контроля «последний ответ примера». Иначе это копирование ответа примера.

### Мера
AUC разности логитов против истинного знака (для последнего исхода — против исхода); точность по знаку разности — описательно.

### Основная семья
Знак, окно 32, 10 наборов. Точные парные перестановочные тесты по наборам, **односторонние** (направление задано). Холм по всем восьми проверкам. Минимально возможное p — 0,001, после Холма — 0,008.

Для каждой модели (160M, 1B) и каждого режима (zero-shot — среднее по трём шаблонам; few-shot):
- **Q1:** AUC предобученной > AUC случайной;
- **Q2:** AUC предобученной > AUC копирования.

**Толкование (записано заранее):**
- Q1 и Q2 в zero-shot — состояние тела доступно языку через смысл слов;
- Q1 и Q2 только в few-shot — аппарат по контексту учится отвечать о теле, без знания смысла (при оговорке выше: выше «последнего ответа примера»);
- зонд высок, а Q1 / Q2 нет — состояние в представлении есть, но языковому каналу не доступно;
- падение при перемешанном окне — ответ опирается на порядок событий, а не на мешок символов.

Для каждого условия указывается доля от зонда: (AUC − 0,5) / (AUC зонда − 0,5).

**Формально выполнены все восемь. По толкованию с оговоркой, записанной заранее:**
1. **Few-shot — копирование ответа примера, а не доступ к телу.**
   - AUC 0,974 / 0,973 равна контролю «последний ответ примера» (0,975), а не превышает его.
   - Перемешанный порядок кадров ничего не меняет (0,974 / 0,975): окно не используется.
   - Случайная LM копирует хуже (0,51–0,58; с произвольными символами — 0,63). Предобученный аппарат лучше копирует ответ из контекста, то есть Q1 в few-shot меряет копирование.
   - По правилу, записанному заранее, few-shot не считается доступом к телу.
2. **Zero-shot — слабый, но устойчивый доступ.**
   - AUC ≈ 0,61 у обеих моделей при 0,48–0,53 у случайной и 0,559 у копирования (Q1, Q2 выполнены, 9–10 из 10).
   - Это **≈ 22 % от зонда:** (0,607 − 0,5) / (0,978 − 0,5) ≈ 0,22 у 160M и 0,23 у 1B.
   - Перемешанное окно не снижает AUC: сигнал опирается на мешок символов, а не на порядок событий.
   - Формально это исход «состояние тела доступно языку через смысл слов». Но по величине он близок к исходу «зонд высок, а языковому каналу почти не доступно»: в представлении знак читается на 0,98–0,99, через логиты ответа — на 0,61.
   - Почему это не копирование вида последнего съеденного — последний пункт в «Описательно».
3. **Размер модели (1B против 160M) zero-shot не меняет** (0,61 / 0,61); зонд у 1B выше (0,993 против 0,978).

Установлено (10 наборов, Холм) — для `flip-2`, интерфейса c + BOS, окна 32, этих шаблонов.

**Описательно:**
- **Последний исход** (' Energy:' → ' up' / ' down'): 160M 0,541 (случайная 0,557), **1B 0,770** (случайная 0,459). Переменная почти буквально лежит в окне; у 1B она заметно доступна языку, у 160M — нет.
- **Что даёт zero-shot сигнал** (выведено, не проверено): мешок символов окна ассоциативно сдвигает предсказание ' A' / ' B'. Например, частота « A … up» против « A … down», а не связка в последнем событии: копирование последнего вида даёт 0,559, перемешивание не мешает.

### Итог по звену 4
- Состояние тела, которого нет в окне буквально (знак), **в представлении есть почти полностью** (зонд 0,98–0,99).
- **Языковому каналу без обучения оно доступно слабо**: zero-shot AUC 0,61, ≈ 22 % от зонда, без опоры на порядок событий и без выигрыша от размера до 1B.
- Few-shot с примерами из того же эпизода — копирование ответа примера, а не отчёт о теле.
- Переменная, почти буквально лежащая в окне (последний исход), у 1B доступна заметно лучше (0,77).
